## 1. 项目边界

受控内容沙盒用于验证“内容平台在用户授权后，把当前内容引用和短期访问授权交给守护者”这一思路。沙盒包含受控内容 Android App、最小平台内容网关、固定演示内容和跨 App 通信，不负责 MiMo 调用、网页检索、真假判断、核验任务或报告展示。

```text
受控内容 App
  -> 展示视频、音频、文章、图文、单图/多图
  -> 打开评论或转发面板时只通知“当前存在候选内容”
  -> 收到守护者主动请求后快照当前内容并申请一次性 grant

平台内容网关
  -> 签发和兑换一次性 grant
  -> 返回 Content Manifest 与可分析资源 URL

守护者 App/后端
  -> comment/share 后让悬浮球进入可用提示态，不自动取资源
  -> 用户点击悬浮球后由守护者向前台沙盒请求当前上下文
  -> 接收并校验带新鲜 grant 的上下文
  -> 读取 Manifest 和资源
  -> 执行缓存、分析、检索和报告流程
```

## 2. 已确认范围

- Android 真机是必须验收的平台，Web 结果不能代替真机；
- 最终 App 必须从零创建，不迁移旧原型代码；
- 开发者预置内容，普通用户不上传；
- 支持 `video`、`audio`、`article`、`rich_article`、`image_gallery`；
- 普通浏览和页面停留不发送上下文，也不启动分析；
- `comment`：打开评论面板时发送候选通知，不表示提交，不传评论正文，不自动取资源；
- `share`：打开转发面板时发送候选通知，不表示分享完成，不传联系人，不自动取资源；
- `guardian_request`：用户点击守护者悬浮球后，由守护者主动请求当前内容；这是唯一启动资源获取的跨 App 触发；
- 用户无需先打开评论或转发面板；只要沙盒在前台且存在有效当前内容，点击悬浮球即可请求；
- “任何时候”仅指受控内容沙盒在前台且正在展示有效内容，不扩展到第三方 App，不使用无障碍或屏幕抓取；
- 广播只传 JSON 上下文，不传媒体二进制、Cookie、联系人、评论正文和长期凭据；
- 守护者缺失、网关失败或媒体失败时，沙盒仍可继续浏览和互动；
- 推荐实现路线是 Flutter + Dart 页面、Kotlin MethodChannel + Android 显式广播；
- Android App 不建设普通用户上传入口；允许独立的开发者管理服务上传 OSS，并由服务端
  计算 URL、元数据和 SHA-256、生成 Manifest 1.0、原子更新运行时 registry。

## 3. 已批准目标协议

2026-08-02 已批准以下 Context 2.2 目标合同。包名、既有响应 Action、Extra、Manifest、Provider 和 Audience 保持不变，只增加守护者到沙盒的主动请求 Action 和请求 ID：

```text
沙盒 applicationId: com.mimotrust.controlledcontent
守护者 applicationId: com.mimotrust.guardian
MethodChannel: com.mimotrust.controlledcontent/context
Request Action: com.mimotrust.intent.action.REQUEST_CONTENT_CONTEXT
Request target package: com.mimotrust.controlledcontent
Request Extra: request_id
Response Action: com.mimotrust.intent.action.CONTENT_CONTEXT
Response target package: com.mimotrust.guardian
Response Extra: payload
Target Context Schema: 2.2
Manifest Schema: 1.0
Provider ID: mimotrust_sandbox
Audience: mimotrust_guardian_backend
```

`guardian_request` 响应中的 `event_id` 必须等于守护者生成的 `request_id`，用于请求关联和端到端幂等。`comment/share` 使用 `content_access.mode = deferred_grant`，不得包含可兑换 grant；`guardian_request` 使用 `content_access.mode = grant_exchange`，由沙盒即时申请默认 180 秒、单次兑换的 grant。

当前 main 分支 Guardian 严格接受 Context 2.2，不再兼容沙盒旧版 2.1 APK。双方联调必须安装
本次 2.2 Debug APK；不得把悬浮球点击伪装成 `comment` 或 `share`。

展示品牌和英文标识已恢复并统一为 `MiMoTrust`，代码、包名和协议使用小写技术标识 `mimotrust`。不再保留其他候选品牌。

## 7. 下一阶段停止条件

- Debug APK 可安装并运行；
- 五类内容至少各有一条可浏览样例，视频至少三条；
- 当前音视频唯一播放，切页后旧媒体停止；
- `comment/share` 只使悬浮球提示可用，不触发 grant 兑换、后台提交或资源下载；
- 沙盒前台有有效内容时，无需先触发 `comment/share`，点击悬浮球也能获得正确当前上下文；
- 沙盒退后台或无有效内容时，守护者在 3–5 秒内结束请求并显示不可用；
- `guardian_request` 返回正确内容及音视频位置、文章进度或图片下标，并携带新鲜一次性 grant；
- 连续点击悬浮球不会产生重复核验任务；
- grant 正常时只可兑换一次，过期、重放和错误 audience 被拒绝；
- 守护者能够接收 Payload 并由后端读取 Manifest/资源；
- 相同内容第二次分析能够展示缓存命中链路；
- 沙盒、守护者或网关任一方不可用时，其他界面不崩溃；
- 完成 Android 真机验收并归档证据。

## 8. 开发者内容上架约定

1. 开发者通过 SSH 隧道访问独立的 `content_admin` 管理页面；
2. 选择内容类型、填写规范元数据并上传一个或多个资源；
3. 服务端统一 MIME、文件名和文本编码，提取媒体属性并计算 SHA-256；
4. 管理员检查 Manifest 预览后确认发布；
5. 服务端上传 OSS、写入 Manifest，并原子更新运行时 registry；
6. 平台内容网关自动重载 registry，grant 合同保持不变。

管理能力仅供开发者使用，不进入 Android App。当前 APK 启动时、从后台恢复时或用户手动
刷新时读取 `/v1/feed`；失败则回退到内置三视频。该读取不签发 grant、不发送 Context。
