# 受控内容沙盒下阶段实现交接说明

> 日期：2026-08-01  
> 用途：作为下一次对话的实施上下文  
> 当前目标：完成受控内容 App、最小平台内容网关和 Android 跨 App 联调  
> 内容上架方式：开发者通过阿里云 OSS 控制台手工上传

## 1. 项目边界

受控内容沙盒用于验证“内容平台在用户授权后，把当前内容引用和短期访问授权交给守护者”这一思路。沙盒包含受控内容 Android App、最小平台内容网关、固定演示内容和跨 App 通信，不负责 MiMo 调用、网页检索、真假判断、核验任务或报告展示。

```text
受控内容 App
  -> 展示视频、音频、文章、图文、单图/多图
  -> 在打开评论或转发面板时发送当前内容上下文

平台内容网关
  -> 签发和兑换一次性 grant
  -> 返回 Content Manifest 与可分析资源 URL

守护者 App/后端
  -> 接收并校验上下文
  -> 读取 Manifest 和资源
  -> 执行缓存、分析、检索和报告流程
```

## 2. 已确认范围

- Android 真机是必须验收的平台，Web 结果不能代替真机；
- 最终 App 必须从零创建，不迁移旧原型代码；
- 开发者预置内容，普通用户不上传；
- 支持 `video`、`audio`、`article`、`rich_article`、`image_gallery`；
- 普通浏览和页面停留不发送上下文，也不启动分析；
- `comment`：打开评论面板时发送，不表示提交，不传评论正文；
- `share`：打开转发面板时发送，不表示分享完成，不传联系人；
- 广播只传 JSON 上下文，不传媒体二进制、Cookie、联系人、评论正文和长期凭据；
- 守护者缺失、网关失败或媒体失败时，沙盒仍可继续浏览和互动；
- 推荐实现路线是 Flutter + Dart 页面、Kotlin MethodChannel + Android 显式广播；
- 不建设上传页面、上传 API 或自动上传脚本；演示素材由开发者手工上传 OSS，并手工维护 URL、元数据、Manifest 和 registry。

## 6. 下一对话的实施顺序

1. 最多确认三项：`com.mimotrust.*` 合同是否正式冻结、最低 Android 版本/目标手机、守护者 Receiver 是否已经存在；
2. 冻结 Context Schema 2.1，创建五类正例和必要反例；
3. 实现最小平台内容网关：`GET /health`、`POST /v1/context-grants`、`POST /v1/grants/exchange`；
4. 用固定 JSON 先跑通“申请 grant -> 一次兑换 -> 返回 Manifest”；
5. 从零创建 Flutter Android 工程并先跑通空项目；
6. 按“静态 Feed -> 五类渲染 -> 音视频播放 -> 点赞/评论/转发 -> MethodChannel -> 显式广播”实现；
7. 先用一条视频端到端联调，再扩展其余内容类型；
8. 构建 Debug APK，安装真机，验证快速切页、后台、断网、守护者缺失和资源失败；
9. 保存 APK、SHA-256、广播发送/接收日志、网关兑换日志和录屏；
10. 达到验收标准后冻结，不继续建设上传、推荐、账号或真实社交功能。

## 7. 下一阶段停止条件

- Debug APK 可安装并运行；
- 五类内容至少各有一条可浏览样例，视频至少三条；
- 当前音视频唯一播放，切页后旧媒体停止；
- `comment/share` 两种触发发送的是当前内容及正确查看状态，普通停留不发送；
- grant 正常时只可兑换一次，过期、重放和错误 audience 被拒绝；
- 守护者能够接收 Payload 并由后端读取 Manifest/资源；
- 相同内容第二次分析能够展示缓存命中链路；
- 沙盒、守护者或网关任一方不可用时，其他界面不崩溃；
- 完成 Android 真机验收并归档证据。

## 8. 手工内容上架约定

1. 开发者在阿里云 OSS 控制台选择并上传文件；
2. 在控制台取得资源 URL、MIME、大小和必要的音视频/图片属性；
3. 在本地计算每个资源的 SHA-256；
4. 手工创建或更新对应 Content Manifest；
5. 手工更新 `content_registry/registry.json` 的顺序和状态；
6. 运行本地校验后再交给沙盒 App 和平台内容网关读取。

内容上传操作全部在项目外手工完成。平台网关生成运行时读取授权不属于内容上传任务，仍按既定 grant 合同实现。
