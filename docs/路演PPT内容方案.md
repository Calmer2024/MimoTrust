## 第 3 页：作品目标及研究方向（30s）

### 选择这个方向的原因

> 2026 年 7 月，小米新车 SkyNomad 澎程尚无量产交付，网上已出现"起火""车祸""车主维权"短视频。答案只隔着一次搜索，但核验行为从未发生。

（PPT 上放 1-2 张当时的真实搜索联想截图，增强说服力）

### 项目的必要性

> **问题不是"互联网上没有答案"，而是"答案没有在用户相信、评论和转发之前到达"。**

用户面对的四个连续障碍：
1. 不知道视频中究竟有几条可以核验的事实主张
2. 不知道应当使用什么中性关键词搜索
3. 无法判断十篇相似文章是否只是同一来源的转载
4. 即使找到资料，也难以比较时间、地点、对象和条件是否一致

传统路径："暂停视频 → 复制信息 → 离开应用 → 组织关键词 → 筛选来源 → 回到原页面" **六步操作**。

信源守护者："继续浏览 → 看到提示 → 按需展开" **三步体验**，只有最后一步需要用户主动参与。

### 项目目标

> 不是事后辟谣工具，而是**传播前的证据辅助**——在用户评论、转发之前，把证据状态送到当前页面。

### 未来愿景

> 让信源核验成为 HyperOS 的系统级能力：在用户需要表达、传播或决策之前，自动整理事实主张、原始来源和证据冲突。"让证据在传播之前到达，让判断仍然属于用户。"

## 第 4 页：作品阐述（60s）

### 作品方向

> "信源守护者"是基于 Xiaomi MiMo-V2.5 的多模态信源核验 Agent。用户无需离开当前页面，系统在后台完成内容理解、信源检索和证据比对，在传播节点提供可追溯、可复查的证据路径。

产品定位：**信息可信辅助能力**，不是内容审查工具，不是自动裁决机构。

核心原则：**不拦截、不说教、不替用户判断**。

### 6 维度阐述

#### 1. 作品创新性（5 个转向）

| 传统做法 | 信源守护者 |
|----------|-----------|
| 事后辟谣 | **传播节点辅助** — 在评论/转发前介入 |
| 字幕关键词匹配 | **多模态主张理解** — 画面+语音+字幕+标题联合理解 |
| "真/假"标签 | **可追溯证据链** — 主张→来源→证据→关系→限制 |
| 模型自由回答 | **证据约束生成** — 只能引用已固化证据，程序校验 |
| 权威白名单 | **领域化证据门槛** — 政策/医学/人物言论用不同标准 |

（PPT 用一张对比表，左侧灰色"传统"，右侧彩色"信源守护者"）

#### 2. 技术领先性

**MiMo 不是装饰性对话入口，而是主链路推理核心**，承担 6 项关键能力：

1. 融合理解视频画面、语音、字幕和标题
2. 区分事实陈述、观点、预测、讽刺和情绪化表达
3. 将复杂内容拆分为可检索、可比对的原子主张
4. 根据主张类型生成中性检索计划
5. 判断证据对主张的支持、反驳、限定或无关关系
6. 在证据范围内生成中立、易读的核验报告

**7 阶段模块化核验流水线（M1-M7）**：

```
M1 输入规范化 → M2 检索规划 → M3 并发检索(Exa) → M4 证据归一化
→ M5 证据初筛(MiMo Pro) → M6 综合研判(MiMo Pro) → M7 报告渲染
```

两个档位：`speed`（快速粗筛）/ `quality`（M6 开启深度思考）

**受控内容沙盒协议（Context 2.2）**：跨 App 内容传递 + grant 兑换机制 + SHA-256 校验

（PPT 放一张流水线架构图或时序图）

#### 3. 应用场景

**覆盖 7 大平台**：抖音、哔哩哔哩、YouTube、快手、微博、小红书、视频号

**三种输入方式**：
- URL 分享（平台链接 / 分享口令）
- 纯文字 / 多模态上传（图片 + 视频 + 音频）
- 受控内容沙盒（跨 App 自动获取）

**三个触发节点**：
- 评论/转发前非打断提示
- 侧边栏 / 小爱一句话唤出
- App 内对话式核验

#### 4. 用户体验

**五项设计原则**：
1. 提醒而不拦截 — 提示醒目但可忽略
2. 帮助而不裁决 — 描述证据，不说教
3. 证据先于结论 — 每个结论关联已保存证据
4. 明确表达不确定性 — 证据不足时返回"暂无法确认"
5. 授权最小化 — 只处理用户主动授权的内容

**适老设计**：大字号、语音解释、一步核验

（PPT 放 App 实际截图：聊天界面 + 核验结果 + 悬浮球）

#### 5. 商业价值

| 产品方向 | 服务对象 | 可持续模式 |
|---------|---------|-----------|
| 系统级可信助手 | 小米手机/平板/浏览器用户 | HyperOS 核心体验；高级家庭功能纳入会员 |
| 企业核验 API | 浏览器、内容平台、搜索与客服 | 按调用量/并发量/年度订阅 |
| 垂直领域方案 | 医疗科普、食品安全、金融反诈 | 私有化部署/行业版本授权 |
| 可信内容工作台 | 媒体、品牌客服、公共传播 | SaaS 席位订阅 |
| 教育与社区 | 学校、社区、公益组织 | 项目采购/公益共建 |

**商业闭环**：更多入口 → 更多场景 → 更丰富证据图 → 更低边际成本 → 更好体验 → 更多入口

#### 6. 作品完成度

48 小时内完成端到端可演示原型：

| 层 | 技术栈 | 状态 |
|----|--------|------|
| 受控内容沙盒 | Flutter + Python 网关 | ✅ 完成 |
| Android App | Kotlin + Jetpack Compose + Room | ✅ 完成 |
| 后端核验服务 | FastAPI + MiMo + Exa | ✅ 完成 |

3. 证据不足（系统主动拒绝判断，不靠模型知识补全）

## 第 5 页：产品演示（60s）

**录屏脚本**：

```
0-5s    打开沙盒 App，浏览一条视频（SkyNomad 事故传言）
5-10s   点击评论按钮，沙盒发送 Context 2.2 广播
10-15s  小真悬浮球亮起（橙色闪烁），点击悬浮球
15-20s  App 打开，显示"正在读取分享内容"
20-25s  进度推进："正在理解文字与画面 → 正在整理待核验主张"
25-35s  继续推进："正在检索公开来源 → 正在筛选证据关系 → 正在综合研判"
35-45s  核验完成，展示结果：
        - 综合判定："时间线存在关键差异"
        - 逐项核验 3 条主张（每条有判定 + 依据）
        - 叙事分析
        - 待补证据
        - 关键依据（4 条，可点击跳转）
45-55s  点击一条关键依据，跳转到原始报道页面
55-60s  返回 App，展示完整报告
```

**录制建议**：
- 用真机录屏（Android 自带录屏功能）
- 后端指向云服务器 `47.94.58.72:8000`
- 提前跑一遍确认链路通畅
- 如果 60 秒不够，可以剪辑加速中间等待部分

## 第 6 页：社会与商业价值（30s）

### 社会价值（6 场景）

| 场景 | 当前问题 | 我们的价值 |
|------|---------|-----------|
| 中老年人 | 不熟悉检索，受标题和情绪影响 | 大字号 + 语音 + 一步核验 |
| 家庭群 | 直接反驳产生对抗，谣言借信任扩散 | 中立证据卡片，减少对抗 |
| 医疗/食品 | 错误信息影响真实生活决策 | 专业来源 + 适用条件 + 不确定性 |
| 灾害突发 | 旧图错配视频传播迅速 | 时间地点核对，避免过早下结论 |
| 学校社区 | 数字素养停留在抽象课程 | "如何看来源"转化为日常实践 |
| 公共讨论 | 真假标签变立场对抗 | 可复查证据替代权威说教 |

**核心指标**：不是"拦截了多少内容"，而是"多少用户在传播前看到了证据"。

### 对小米生态的价值

- **HyperOS 差异化**：系统级当前内容上下文，独立 App 做不到
- **小爱升级**：从回答问题到理解当前屏幕、主动组织证据
- **MiMo 标杆**：展示全模态理解 + 工具编排 + 长链路推理的综合能力
- **适老关怀**：增强小米设备对中老年家庭的长期价值

### 答辩准备

评审可能问的问题：

1. **"MiMo 在你们项目中具体做了什么？不是只用来聊天吧？"**
   → MiMo 是主链路推理核心，承担 6 项能力：多模态理解、主张拆分、检索规划、证据初筛、综合研判、报告生成。不是装饰性对话入口。

2. **"你们怎么保证核验结果的准确性？"**
   → 三个约束：① 只引用已固化证据，不靠模型知识补全；② 程序化校验引用真实性、时间线闭合、结论强度；③ 证据不足时主动返回"暂无法确认"，不硬判。

3. **"这个和现有的辟谣平台有什么区别？"**
   → 三个根本不同：① 传播前介入，不是事后纠错；② 可追溯证据链，不是真假标签；③ 非打断式交互，不拦截不阻塞。

4. **"怎么在小米生态中落地？"**
   → 短期：独立 App + 系统分享接入。中期：接入 HyperOS 当前内容上下文、侧边栏、小爱入口。后端核验主链不需要重写。

5. **"48 小时做了多少？哪些是真正跑通的？"**
   → 端到端链路全部跑通：沙盒分享 → App 接收 → 后端核验 → 报告生成。三个案例验证：时间线冲突、语境误导、证据不足。

6. **"用户隐私怎么保证？"**
   → ① 只处理用户主动授权的单条内容，不持续监控；② 不读取评论输入；③ 允许取消任务并删除结果；④ 日志不记录私人正文。
